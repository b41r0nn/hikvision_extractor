EVIDENCIA: Comportamiento de backfill en BD nueva sin extracciones previas
Fecha: 29 de julio de 2026
Proposito: investigar que ocurre con ultima_extraccion_exitosa cuando la tabla
configuracion esta vacia, recien migrada, sin ninguna extraccion historica.

CODIGO RELEVANTE

1. backend/config_service.py:99-109

    def set_ultima_extraccion(db: Session, when: Optional[datetime] = None) -> None:
        if when is None:
            when = datetime.now(timezone.utc)
        set_valor(db, ULTIMA_EXTRACCION_KEY, when.isoformat())

    def get_ultima_extraccion(db: Session) -> Optional[str]:
        val = get_valor(db, ULTIMA_EXTRACCION_KEY, "")
        return val or None

Observacion: no hay default en codigo ni en la migracion. Si la clave no existe
en la tabla `configuracion`, `get_ultima_extraccion` devuelve `None`.

2. backend/main.py:80-153 (bloque de backfill del lifespan)

    try:
        db = SessionLocal()
        try:
            ultima_iso = config_service.get_ultima_extraccion(db)
            if ultima_iso:
                ultima_date = date.fromisoformat(ultima_iso[:10])
                hoy = hoy_bogota()
                if ultima_date < hoy:
                    start_backfill = ultima_date + timedelta(days=1)
                    end_backfill = hoy
                    print(f"[BACKFILL] Rellenando desde {start_backfill} hasta {end_backfill}...")
                    ...
                else:
                    print("[BACKFILL] Ultima extraccion es hoy; no se requiere relleno.")
            else:
                print("[BACKFILL] No hay ultima extraccion registrada; se omite backfill.")
        finally:
            db.close()
    except Exception as e:
        print(f"[BACKFILL ERROR] No se pudo evaluar backfill: {e}")

Conclusion: cuando `ultima_iso` es `None`, el backfill NO se ejecuta. No intenta
una fecha arbitraria ni la mas antigua posible del dispositivo; simplemente
omite el backfill.

3. backend/scheduler.py:11-25 (job diario programado)

    def tarea_extraccion_diaria():
        print("[SCHEDULER] Ejecutando extraccion diaria programada...")
        try:
            print("[EXTRACCION] Disparador: scheduler (cron hour=20, minute=0)")
            extractor_hikvision.main()
            db = SessionLocal()
            try:
                set_ultima_extraccion(db)
            finally:
                db.close()
            print("[SCHEDULER] Extraccion diaria completada y registrada.")
        except Exception as e:
            print(f"[SCHEDULER ERROR] Extraccion diaria: {e}")

Conclusion: el primer job diario a las 8:00 PM extrae SOLO el dia de hoy (comportamiento
por defecto de extractor_hikvision.main()) y, si tiene exito, registra la primera
ultima_extraccion_exitosa. A partir de ahi, el backfill del lifespan funciona.

PRUEBA REALIZADA

Se creo una base de datos SQLite limpia y se ejecuto `get_ultima_extraccion`:

    from backend.database import SessionLocal
    from backend.config_service import get_ultima_extraccion

    db = SessionLocal()
    print(repr(get_ultima_extraccion(db)))

Resultado:

    None

No hay ultima extraccion registrada en una BD nueva.

IMPLICAIONES PARA EL DEPLOY

- Al migrar una BD nueva o una BD sin historial de configuracion, el backfill
  del arranque NO recupera dias pasados automaticamente.
- El admin debe hacer la primera extraccion manual (boton "Actualizar
  marcaciones") o esperar al job de las 8:00 PM para que se registre la primera
  ultima_extraccion_exitosa.
- Si se necesita cargar historial, se debe usar POST /api/extraer con un rango
  explicito (por ejemplo, fecha_inicio=2026-07-01, fecha_fin=hoy).

Resultado: investigacion cerrada. El codigo maneja el valor ausente como
None y omite el backfill; no hay fecha arbitraria ni fallo.
