EVIDENCIA: endpoint /health sin autenticacion y healthcheck de produccion
Fecha: 29 de julio de 2026
Proposito: verificar que el endpoint /health responde 200 sin JWT y que /api/status sigue protegido (401 sin auth).

Comando ejecutado:

    .venv-test\Scripts\python.exe -c "
    import os
    from fastapi.testclient import TestClient
    from backend.main import app

    client = TestClient(app)

    # Probar /health
    response = client.get('/health')
    print('Status:', response.status_code)
    print('Body:', response.json())
    assert response.status_code == 200, f'Expected 200, got {response.status_code}'
    assert response.json()['status'] == 'ok'
    print('TEST /health: PASS')

    # Probar que /api/status requiere auth (confirmar el problema original)
    response_protected = client.get('/api/status')
    print('/api/status without auth:', response_protected.status_code)
    assert response_protected.status_code == 401, f'Expected 401, got {response_protected.status_code}'
    print('TEST /api/status protected: PASS')
    "

Salida:

    Status: 200
    Body: {'status': 'ok'}
    TEST /health: PASS
    /api/status without auth: 401
    TEST /api/status protected: PASS

Observaciones:
- El endpoint /health realiza un SELECT 1 contra la base de datos via SQLAlchemy.
- No requiere autenticacion ni RBAC.
- Si la conexion a la BD falla, devuelve HTTP 500.
- El healthcheck de docker-compose.prod.yml fue actualizado para usar:
      wget -qO- http://localhost:8000/health || exit 1
- El endpoint /api/status continua protegido con JWT (401 sin token), confirmando
  que el problema original del healthcheck mal targeteado fue corregido.
